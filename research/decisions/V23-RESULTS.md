# V2.3 — 对象工具重构与验收边界

2026-09-24。基线：Plugin `3a99913`、Mod `dff95bc`、Bench `7d0694a`。
本版完成对象读取入口收敛。真实 Agent 实验支持能力发现的减负，尚不支持
“复杂组合推理整体变好”或“所有问题轮次更少”的结论。

## 实际交付

- 新能力连接下 `look` 统一身份、Pawn 专项、设备状态和最终属性；Agent 不再
  同时看到 `look` 与 `inspect_state` 两套对象入口。旧 Mod 保留原接口。
- `count` 保持统计职责。`look/count` 的 Thing capability 筛选复用原生谓词，
  先筛选再计数/分页，不靠原版建筑/药物定义白名单，不读取环境。
- 单个明确对象的原生专项读取在内部一次解析、一次观察完成。精确名称规则、
  全地图/当前地图默认与原查询一致。人群和复合选择器保留原查询编译器并内部分批。
- `survey_space` 查区域环境，`inspect_route` 查沿途环境，`inspect_space` 保留
  轻量可达性/排序。未引入救援特化工具、综合安全分数或动作可行性承诺。
- 逐次原始观察、读取时刻、unknown 和列表完整性保留。大小分页只省略整行，
  给出 next_offset；续页是新观察，不是冻结快照。单对象和原生单批仍有大小上限。
- 预约快照按需初始化；技能专项和 cell identity 不再扫描预约表。

## 封存真实 Agent 实验

同一暂停原生世界，旧 Plugin 4 题、新 Plugin 8 题，12 个槽各一次；模型
`deepseek-flash`。基线与候选都接新版 native backend，因此是适配器对照，
不是历史 Mod 二进制对照。完整答案、短答、每次工具选择和原生回执由两名
独立审查者复核；status=ok 只代表交付，不代表正确。

| 对照题 | 旧版核心/模型请求/原生业务读取 | 新版核心/模型请求/原生业务读取 |
| --- | --- | --- |
| 医疗技能 | 通过 / 2 / 2 | 通过 / 2 / 3 |
| 床药发现 | 通过 / 4 / 7 | 通过 / 3 / 3 |
| 指定伤员与搬送者的床位检查 | 失败 / 4 / 6 | 通过 / 7 / 12 |
| 综合救援 | 失败 / 5 / 7 | 失败 / 7 / 12 |

对照核心 2/4 → 3/4。发现题非提交工具输出 80,695 → 19,579 字符（约减76%），
新版未调用环境扫描。床位虽然答对核心问题，但经历身份查询超时和上下文参数修复，
不能称为交互效率已经通过。技能题当时仍走身份中转，原生读数反而增加。

候选另外4道迁移题：实际属性、取药路线、生产条件、人数范围，核心均通过；
严格按需求计3/4，人数题虽人数正确，却违反“只报告人数与范围”，额外枚举人群。
模型请求分别3、6、3、3。取药仍重复使用轻量路径与完整路径，交付修复两次。
生产题正确保留食材、未知组件与作业资格的不确定性。

救援仍失败：没有读取最终 MoveSpeed、指定人物床位上下文和搬送路线；
短答把22单位药全部绑定到实际仅10单位的一堆；对伤病影响和危险覆盖仍有过度概括。
这些不能用“工具能返回这些数据”或后续单元测试代替 Agent 验收。

基线4题共15次模型请求、458,713报告tokens、22次业务读取；候选8题共34次请求、
730,315报告tokens、54次业务读取。任务数量不同，不能比较这两个总数作为节省率。
12次均正常交付。未以反复运行同一失败槽覆盖原始分数。

## 评测后的通用修复（不追改原评分）

1. 兼容旧 `quantity` 与状态专项的组合；`distribution` 仍应使用 count。
2. actor/user schema明确只能填ID或名称之一，避免同时填两者。
3. 嵌套列表完整性校验绑定真实所属对象，不再让技能“医疗”匹配床位的“全部医疗标记”。
   对原失败稿和原回执回放：旧 `[incomplete_quantifier_claim, health_completeness_claim]`，
   新 `[health_completeness_claim]`。真正无证据的“无伤情”仍拒绝，根人口/物资约束保留。
4. 单个明确对象直读消除身份中转，保留精确匹配与地图范围；不影响旧空间工具名字解析。

上述修复由确定性/native回归确认，未追加付费模型尝试，也没有把原技能/床位轮次
替换成修复后估计值。新生成回归世界保留随机人物伤病，不与原付费世界混为同一数据集。
旧脚本对 Cataract 和旧存档床ID的硬编码断言先后失败，已改为核对实际损伤结构并从
当前发现结果选择床ID；这些属于回归脚本不适用于新生成世界，失败产物保留。

## 验证与审查

Plugin全量488项通过；随后对象/claim定向84项通过。Bench全量497项通过；
Mod独立输出目录构建、BridgeSmoke通过。构建仍有既有nullable/GraphQL analyzer警告。
最终原生9项检查通过：技能、床位各1次原生读取；capability发现与计数各1次；
专项/完整状态、显式大小边界、cell身份/环境、名称大小写和quantity兼容均通过。
最终范围/分页5项通过：发现与survey对象集合相等、歧义不静默挑选、fog/held范围、
跨原生批次及整行大小分页续页无重叠。新世界发现输出10,544 vs survey73,503字符。
每个部分结果/失败回执保留。

Standards审查：预约无条件扫描已改为按需读取，无剩余行动项。
Spec审查：精确大小写、完整/短标签选择、无CurrentMap的全加载地图查找已修复。
没有覆盖正常游戏DLL；使用独立开发存档与只读host。无游戏写入/救援执行能力。

主要剩余限制是 Agent 取证选择和跨事实整合，简单计数过度查询、长回答修复与复杂
救援缺证仍需单独解决。当前结果不支持再靠堆叠提示词就能解决这些问题。

`experiments/v23/`。凭据精确扫描938个源文件/产物未检出，私有临时配置已删除。
